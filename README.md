# Mini AI ERP

Учебный шаблон мини-ERP: **FastAPI + SQLite + React + LLM**.
AI-фича: пользователь задаёт вопрос по-русски → LLM пишет SQL → бэкенд безопасно выполняет его → результат в таблице.

## Как запустить

Нужно два терминала.

**1. Бэкенд** (порт 8000):
```bash
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env      # и вставь ключ ANTHROPIC_API_KEY
uvicorn main:app --reload
```
Документация API открывается сама: http://localhost:8000/docs

**2. Фронтенд** (порт 5173):
```bash
cd frontend
npm install
npm run dev
```
Открыть http://localhost:5173

## Архитектура

```
Браузер (React)  ──HTTP /api/...──►  FastAPI (main.py)  ──SQL──►  SQLite (erp.db)
                                          │
                                          └── /api/ask ──► ai.py ──► Claude API
                                                             │  (вопрос + схема БД → SQL)
                                                             └── проверка SELECT → выполнение read-only
```

| Файл | Что делает |
|---|---|
| `backend/db.py` | Схема таблиц, подключение к БД, тестовые данные |
| `backend/main.py` | REST API: товары, клиенты, заказы, статистика, AI-вопрос |
| `backend/ai.py` | Text-to-SQL: промпт со схемой → LLM → проверка → выполнение |
| `frontend/src/App.jsx` | Интерфейс: 4 вкладки (дашборд, товары, заказы, AI-аналитик) |
| `frontend/vite.config.js` | Прокси: запросы `/api` уходят на бэкенд |

### Модель данных
- `customers` — клиенты
- `products` — товары с ценой и остатком на складе
- `orders` — заказы (связь клиент ↔ товар), сумма, статус `new/paid/shipped`

### Бизнес-логика
При создании заказа бэкенд проверяет остаток, считает сумму и **списывает товар со склада** — в одной транзакции.

### Безопасность AI-фичи (важно рассказать на интервью)
1. LLM получает в промпте только **схему**, а не сами данные.
2. Сгенерированный SQL проверяется: только один `SELECT`, без `DROP/DELETE/...`.
3. Запрос выполняется через **read-only подключение** — даже если проверка пропустит что-то, БД изменить нельзя.
4. Пользователю показывается сам SQL — результат можно проверить.

## Шпаргалка к интервью

- **REST API** — бэкенд отдаёт данные по URL: `GET /api/products` — получить список, `POST /api/products` — создать.
- **Почему FastAPI** — быстро, автоматическая документация `/docs`, валидация входных данных через Pydantic.
- **Почему SQLite** — ноль настройки для прототипа; в проде заменить на PostgreSQL (SQL почти тот же).
- **Как фронт общается с бэком** — `fetch('/api/...')`, JSON туда и обратно.
- **Что улучшить дальше** — авторизация и роли, PostgreSQL, миграции (Alembic), деплой в Docker, история AI-запросов, графики на дашборде, AI-прогноз остатков.
